# H700 platform: what all models share

Evidence for phase P1. Source: the 19 device trees and 10 panel firmware files in ROCKNIX's **20261001** H700 image (the image Handtop builds from), summarised in [h700-20261001-facts.json](h700-20261001-facts.json) by `ports/tools/dt-facts.py`; ROCKNIX's H700 kernel patches and quirks at the same tag ([source tree](https://github.com/ROCKNIX/distribution/tree/20261001/projects/ROCKNIX/devices/H700)).

## The same on every model

- **One kernel, one U-Boot per RAM type.** ROCKNIX ships one H700 image per RAM type (DDR4, DDR3) with every model's device tree; only `dtb.img` differs between models. Handtop's kernel modules (Cedrus, FunctionFS for XInput, uhid, the fixed joypad driver) are built for that one kernel and load on every model.
- **Gamepad driver and name:** every device tree uses `rocknix-singleadc-joypad` named "H700 Gamepad", with the same 17 button codes (D-pad, A/B/X/Y, L1/R1/L2/R2, L3/R3, Select, Start, F). The input daemon's device match works unchanged. Models without sticks still declare the L3 / R3 codes; whether those buttons exist is per model.
- **Volume keys:** the same `gpio-keys` device (Vol+ / Vol−) everywhere. The power key comes from the AXP717 driver (not a device-tree node), and every model has that chip, so it is expected to be the same.
- **Power chip:** AXP717 on every model, so battery, charging and the power key behave the same in the kernel. Handtop's rule against writing to it applies to all.
- **Screen:** every panel is driven by ROCKNIX's generic `panel-mipi-dpi-spi` driver plus a firmware file that holds the panel's size and modes. The backlight is `pwm-backlight` everywhere.
- **LEDs:** power and status on every model.
- **HDMI:** enabled on every model.
- **Wi-Fi and Bluetooth:** the RTL8821CS on every model except the RG35XX 2024 (no radio nodes at all). Handtop's Wi-Fi power-save setting and Bluetooth first-boot check apply wherever the chip is.
- **Video engine:** same SoC, so the video-engine overlay Handtop adds to the H's device tree should apply to every model's (to verify in P2 with the overlay step and on hardware).

| [RG34XX](rg34xx.md) | 720×480 | none | – | Wi-Fi + BT | OTG only | – |
| [RG34XX SP](rg34xx-sp.md) | 720×480 | 4 axes | yes | Wi-Fi + BT | OTG only | base, v2-panel |

- **Screen sizes:** 640×480 (3.5" and 4"), 720×480 (3.4", 3:2), 720×720 (CubeXX), and the RG28XX's 480×640 panel mounted sideways (`rotation = 270`).
- **Sticks:** 4 stick axes (`amux-count` 4) or none. The device tree can't say how many sticks exist physically (the RG40XX V declares 4 axes).
- **Axis inversion:** the left stick is inverted on every model; the right stick additionally on the RG40XX H, CubeXX and RG34XX SP. That is done in the kernel, so the input daemon must not invert again.
- **Lid switch** (`SW_LID`, wakes the device): RG35XX SP, RG34XX SP, RG SP.
- **RGB stick LEDs** (`kbd_backlight` plus a serial port ROCKNIX uses to set colours): RG40XX H, RG40XX V, CubeXX.
- **Motor:** PWM channel 2, or 3 on the RG40XX H / V and CubeXX; handled by the device tree.

## USB

The RG35XX H is the only model with a **second, host-only USB controller** enabled (`usb@5200000` / `usb@5200400`: the H's left port, where Handtop says to plug keyboards and hubs). Every other model has only the OTG controller, the port that also charges. On those, a USB keyboard, mouse or hub needs that port in host mode (ROCKNIX carries a patch for OTG host mode, `0151-phy-fix-OTG-host-mode.patch`), and charging while a hub is plugged in depends on the hub. Not tested by Handtop. The External Controller's USB modes use the device side of the same port.

## Panel variants: the open problem

Several models have two panels that need different device trees, and a user can't see which one they have:

| Model | Device trees |
|---|---|
| RG35XX H | base, rev6-panel (Handtop reads pin PE6, found in the stock U-Boot) |
| RG35XX Plus | base, rev6-panel |
| RG35XX 2024 | base, rev6-panel |
| RG35XX SP | base, v2-panel |
| RG40XX H | base, v2-panel |
| RG40XX V | base, v2-panel |
| RG34XX SP | base, v2-panel |

ROCKNIX's advice is to try both ("it's impossible to know the difference (without opening the device)", [H700 installation guide](https://rocknix.org/configure/h700-installation/)). **Anbernic's stock U-Boot does know:** every two-panel model reads pin PE6 at boot, like the RG35XX H (pull-up on for most models, left as the board sets it on the RG35XX SP and RG40XX family). So Handtop's existing panel check covers them all, switched on per model by its profile. Details, and three models where ROCKNIX seems to lack a panel variant: [stock-firmware.md](stock-firmware.md).

## RAM type

ROCKNIX ships DDR4 and DDR3 U-Boot for all H700 models, but no source read so far says which models or batches use DDR3, or how to tell without trying. Handtop's flashing guide already says: no LED at all → flash the DDR3 image. Same assumption for every model until reports say otherwise.
