# Theme

The **Theme** app (`rg35xxh-theme`) picks a theme and applies it at once. Built in: **Handtop (dark)** (default), **Handtop (light)**, **Debian** (a stock Debian desktop: GNOME's Adwaita colours and pointer, Debian red, the apps' own icons; no Debian artwork), **High contrast** (white and yellow on black, lines twice as thick, text 1.25×, a 48 px pointer, GTK's HighContrastInverse) and **Grayscale** (Handtop dark in greys, generated by `tools/icons/gen_grayscale.py`). Since v0.4.0 every theme is a theme folder (the `.handtop-theme` format, below); the app is the only program that reads them.

## Usage

**Apps → Theme** (`handtop_theme/app.py`):

- **Main screen:** the installed themes on the left (built-in first, then **Yours**), each with its background and accent colours; the selected theme's preview (drawn from its colours and images, or its own `preview.png`), name and description on the right. **Apply** switches to it; **Duplicate** makes an editable copy; **Delete** removes one of yours (deleting the current one switches to Handtop dark first). The framed icon buttons above the list are **Import** (a tray with an arrow coming in) and **Export** (a box with an arrow going out); their names show on hover. When a theme's pointer differs from the session's, the app says it changes at the next log-in and offers **Log out now**.
- **Duplicate:** name, accent (the theme's own plus 7 presets), background (its own plus 7), icon set (dark / light, follows the background), pointer size (24 / 32 / 48), text size (100 / 125 %), with a live preview. A new accent or background re-derives the copy from its palette (every part follows; decision 2026-11-10), and a new background drops a wallpaper image (its colour is baked in). Everything else is copied; the copy says "Based on …".
- **Import / Export** open GTK's file chooser, starting in `~/Themes` (created if needed), with `~/Themes` and the boot partition (`/boot/firmware`, shown as "firmware") in its sidebar; USB drives and SD cards appear there by themselves (Other Locations for the rest). It shows `.handtop-theme` files (or all files). Import: a refused file lists every problem (theme.json and images together) and nothing changes; a theme with the same id asks before replacing. Export: the name is prefilled as `<id>.handtop-theme` (the extension is added if left out), GTK asks before replacing a file, and the file has `GUIDE.md` inside. The boot partition is read-only for the desktop user. (Decision 2026-11-10: GTK's chooser, after comparing it with a Handtop-made browser on the device.)
- Escape (B) goes back from a sub-screen.

From a terminal:

| Command | Does |
|---|---|
| `rg35xxh-theme ID` | apply a theme (`dark` / `light` still work: `handtop-dark` / `handtop-light`) |
| `rg35xxh-theme --get` / `--list` | the current theme's id / the installed themes |
| `rg35xxh-theme --import FILE [--replace]` | install a `.handtop-theme` (checked first; refused with the list of problems) |
| `rg35xxh-theme --export ID FILE` | write a theme as a `.handtop-theme` (with `GUIDE.md`) |
| `rg35xxh-theme --ensure` | session start (labwc autostart): render the current theme again if its files are missing or out of date |

The choice is the theme id in `~/.config/rg35xxh/theme` (v0.3.x's `dark` / `light` are read as the built-in themes and rewritten at the next log-in). Built-in themes are in `/usr/share/rg35xxh/themes/`, yours in `~/.local/share/rg35xxh/themes/`.

## How a theme reaches the desktop

Applying renders the theme into **`~/.local/state/rg35xxh/theme/`** (replaced as a whole) and points the session at it. Components read only these files; each falls back to Handtop dark's copy in `/etc` or `/usr/local/share/rg35xxh/icons` when nothing is rendered.

| Part | Reads | Applied |
|---|---|---|
| Taskbar (Waybar) | `waybar.css` via `rg35xxh-themed waybar` | Waybar is stopped; its restart loop (`rg35xxh-waybar`) starts it again |
| Taskbar icons (input mode, battery) | `icons/` (`rg35xxh-inputmode`, `rg35xxh-battery`) | the icon scripts are signalled |
| Notifications (mako) | `mako.conf` via `rg35xxh-themed mako` | restarted |
| Wallpaper (swaybg) | `WALLPAPER*` in `theme.env`, `wallpaper.png` | restarted |
| Window title bars (labwc) | the user theme `Handtop`: `~/.local/share/themes/Handtop/labwc/themerc` links to `labwc/themerc` (a file of your own there wins) | `labwc --reconfigure` |
| App and tray icons | the GTK icon theme **`Handtop-Current`** = `~/.local/share/icons/Handtop-Current` → `icon-theme/` (inherits the theme's GTK icon theme); labwc's window icons too (`<theme><icon>` in `rc.xml`). Handtop's apps name their icons (`Icon=rg35xxh-theme`, ...) | at once in new windows; Waybar's tray after its restart |
| App drawer (nwg-drawer) | `nwg-drawer.css`, copied to `~/.config/nwg-drawer/handtop.css` by `rg35xxh-drawer` | when it opens |
| Power menu (wlogout) | `wlogout.css` (`rg35xxh-power-menu`) | when it opens |
| On-screen keyboard | `COLOR_OSK_*` in `theme.env` | each time it is shown |
| External Controller (app and status screen) | `icons/`, `COLOR_STATUS_*` | when it opens |
| Display app | `COLOR_DISPLAY_*` | when it opens |
| Pointer | `CURSOR_*` in `theme.env`: the session script (`/etc/profile.d/zz-rg35xxh-session.sh`) exports `XCURSOR_THEME` / `XCURSOR_SIZE` before starting labwc (Handtop 24 until a theme is rendered); `--ensure` then gives GTK the same (gsettings `cursor-theme` / `cursor-size`, `settings.ini`) | at the next log-in, labwc and GTK apps together (labwc reads XCURSOR only at start; GTK switching at once made the hand / text pointers over apps a different size from the arrow until then) |
| GTK apps | gsettings `color-scheme`, `gtk-theme`, `icon-theme` (only when it was Handtop's or Adwaita: a theme you chose yourself is left alone), `text-scaling-factor`; the same in `~/.config/gtk-3.0/settings.ini` | open apps may need a restart; the desktop cursor changes at the next log-in |

`theme.env` holds everything as `KEY='value'` lines (`THEME_ID`, `THEME_BASE`, `ICONS`, `WALLPAPER*`, every palette colour as `PALETTE_*`, every part colour as `COLOR_<PART>_<KEY>`); read it as data, never source it. Python apps use `handtop_theme.current` (`/usr/local/lib/rg35xxh-theme`).

`--ensure` compares a stamp (renderer version, theme folder, newest file in it) with `.stamp` in the rendered folder, so a normal log-in costs one quick check; after an update that changes the renderer (`RENDER_VERSION`) or an edited theme, it renders again before anything that reads the files starts. A missing or broken theme falls back to Handtop dark (logged in `~/.local/state/session/theme.log`).

Fonts, cursor, GTK and icon themes are named by a theme; one that is not installed is replaced by Handtop's (Noto Sans, Handtop, Adwaita) when the theme is applied, and logged. GTK's own themes (Adwaita, Adwaita-dark, HighContrast, HighContrastInverse) count as installed. Window title-bar text stays Noto Sans 9 in every theme (it is set in labwc's `rc.xml`, which a user file would replace as a whole; decision 2026-11-10).

The packages' own icons are what a theme gets for `"system"`: since v0.4.0 Handtop's pixel-art replacements for the default apps, Wi-Fi and Bluetooth are no longer installed into `/usr/local/share/icons` but live only in the themes (sources in `src/theme/art/icons/`). The one addition there is `micro.svg` (micro's package names its icon by path).

Your own `~/.config/waybar/style.css` or `~/.config/mako/config` still wins over every theme.

**Terminal:** `~/.config/foot/foot.ini` links to the rendered `foot.ini` (a file of your own there wins); new terminal windows use the theme's colours, open ones keep theirs. Handtop dark and light keep the one dark terminal (decision 2026-10-25); other themes set or derive their own (the 16 ANSI colours keep their meaning: blue stays blue whatever the accent).

**Volume / brightness bar:** `rg35xxh-osd` (C) reads `COLOR_OSD_*` from `theme.env` when the bar shows and the file has changed since (one `stat` per pop-up); Handtop's own colours until a theme is rendered.

**A theme's own pointer, fonts and CSS** (optional files in the theme, never inherited; `extras.py` checks them, `GUIDE.md` lists them; decision 2026-11-11, for the Retro theme):

- **Pointer:** `cursors/<shape>.png` (arrow, hand, text, busy, progress; 48x48, hotspots in `cursor.hotspots`). Rendering writes an Xcursor set (24 and 48 px, `xcursor.py`, inherits `Handtop` for other shapes) to `pointer/`; applying copies it to `~/.local/share/icons/Handtop-Theme-<id>` and the theme's `CURSOR_THEME` is that name. The session script exports `XCURSOR_PATH` with `~/.local/share/icons` first (labwc and libwayland-cursor). Sets with Handtop's mark that are neither the current theme's nor the one labwc runs with (read from labwc's environment, so applying from ssh is safe too) are removed when a theme is applied and at log-in.
- **Fonts:** `fonts/ui.ttf|otf`, `fonts/mono.ttf|otf` (2 MB each, TrueType / OpenType signature, no collections), `fonts/LICENSE.txt`. `fonts.ui` / `fonts.mono` must name the file's family; with `decode` (import, applying a user theme) `fc-scan` must read one family with that name (one face, or the named instances of one variable font). Applying copies them to `~/.local/share/fonts/handtop-theme/` (Handtop's mark inside; replaced by the next theme's, removed when it has none) and runs `fc-cache` before the installed-fonts check.
- **CSS:** `css/apps.css`, `css/taskbar.css`, `css/drawer.css`, `css/powermenu.css` (64 KB, UTF-8, no `@import`, `url()` or backslash). The last three are appended to Handtop's rendered `waybar.css`, `nwg-drawer.css`, `wlogout.css`; `apps.css` is rendered as `gtk.css` (a header only when a theme has none) and `~/.config/gtk-3.0/gtk.css` links to it (a file of your own there wins). GTK reads that file in every GTK 3 program, the taskbar, drawer and power menu included, above their own CSS.
- **GTK text font:** applying also sets gsettings `font-name` / `document-font-name` (`fonts.ui` 9) and `monospace-font-name` (`fonts.mono` 9) and `gtk-font-name` in `settings.ini`, so a theme's text font reaches app windows (before, `fonts.ui` only reached the taskbar, notifications and power menu).

**Downloadable themes** (not in the image): `src/theme/extra/<id>/`, packed by `python3 tools/themes/pack-extra-themes.py <folder>` into `handtop-<id>.handtop-theme` (checked like an import) and attached to the release. **Retro** (`retro`, generated by `tools/themes/gen_retro.py`; fonts W95FA (OFL 1.1) and PxPlus IBM VGA 8x16 (CC BY-SA 4.0), licences in `fonts/LICENSE.txt`): grey bevelled taskbar, drawer and power menu, navy title bars, teal desktop, a cream notification, a black terminal with the 16 VGA colours, 16-colour pixel art for every image slot, its own pointer, and GTK CSS for 90s buttons, fields, menus, tabs and scrollbars (on Adwaita light; GTK 4 apps, Chromium and the Display app keep their own look). **Glass** (`glass`, `tools/themes/gen_glass.py`; Inter variable, OFL 1.1): light see-through panels (labwc cannot blur: tinted translucency) with a bright top edge and a soft shadow, the taskbar drawn as two floating glass capsules over the gradient wallpaper (one chip style for the hovered button and the active window), glass tiles in the drawer and power menu, monotone ink line icons with square ends and mitred corners and no frame of their own (the glass tiles frame them; Jason 2026-11-11), separately drawn 22 / 20 px app icons, a smooth pointer, the accent for selections in GTK apps. **Pocket** (`pocket`, `tools/themes/gen_pocket.py`; Pixelify Sans and VT323, OFL 1.1): meant to feel like a different device, not a recolour (Jason 2026-11-11), within what a theme can change: exactly four greens; a dot-matrix home screen with the POCKET wordmark and "press START" as wallpaper; the taskbar as a dark status strip with Apps as a light START pill (a D-pad mark); hearts for the battery (three, filled in halves); the input-mode icon in desktop mode and the pointer are a pointing glove; game text-box frames (double line) for drawer tiles, power-menu boxes and app frames; its own pixel art (nothing shared with Retro); app icons are game cartridges whose labels show the app (12x12 label sprites, also used light-on-dark as the 22 / 20 px icons for the taskbar and title bars). Images External Controller shows on its light pages carry a dark outline and a light ring so they read on the dark strip too. Not themed: the apps' own icons inside windows (Thunar's folders come from the system icon theme). **Signal** (`signal`, `tools/themes/gen_signal.py`; Space Grotesk and Space Mono, OFL 1.1): a minimal design object (Jason chose "Swiss design object" over an e-ink reader and a typewriter): warm white #f2f2ef and black with one signal red #e8321d, at most one red element per drawing; an abstract poster wallpaper (concentric black rings of falling weight from beyond the lower-left corner and one red disc; no text or layout boxes, Jason 2026-11-11); the Apps button a black block, the active window underlined in red, bold clock and battery; square black-framed drawer tiles and power-menu tiles that fill black / red; geometric icons (drawing helpers from gen_glass.py, drawings its own), pixel-exact images where External Controller enlarges them; red selections and square buttons in GTK apps.

**App names:** a theme's `names` (default apps only) are rendered as `.desktop` copies with only the `[Desktop Entry]` `Name=` changed (its translations dropped, so the new name shows in every language) and the marker `X-Handtop-Theme-Name=true`; applying copies them into `~/.local/share/applications` after removing the previous theme's marked copies. A file of your own with the same name is left alone. `"system"` is the package's own name. The built-in themes rename nothing (Handtop's own names, "Terminal", "File Manager", ..., are the system-wide baseline in `/usr/local/share/applications`).

## History

- v0.2.0: dark / light, one file per component and theme (`style-light.css`, `config-light`, the `Handtop-Light` labwc and icon themes, `-light` icons), switched by the app.
- v0.4.0: themes as data (`src/theme/`). The v0.3.9 configs and palettes are kept in `src/theme/tests/reference/` and the built-in themes are tested to render the same rules and colours.

## Theme files (v0.4.0)

The next Theme app reads themes as `.handtop-theme` files (a zip: `theme.json` + PNG images at fixed paths) that cover every static visual part. The code is `src/theme/handtop_theme/` (installed to `/usr/local/lib/rg35xxh-theme/` by `build/07d-theme.sh`, which also assembles the built-in themes).

| Module | Does |
|---|---|
| `schema.py` | The contract, schema 1: 13 palette colours, 111 per-part colours each with a rule that derives it from the palette, 173 image slots (fixed name, size, required / optional / generated, which may be `"system"`), renameable default apps, import limits |
| `theme.py` | Reads and checks `theme.json`, checks every image, and fills in what a theme leaves out: palette colours from its base theme (`handtop-dark` / `handtop-light`), part colours from its own palette, images from the base (or made from the theme's own: shake frames, 22 / 20 px app icons); a wallpaper image is never inherited |
| `pngcheck.py` | PNG check without a decoder (chunk CRCs, IHDR, image data inflated with a hard limit), then a full decode with GdkPixbuf |
| `imgops.py` | GdkPixbuf: smooth downscale (HYPER) for small app icons, the sideways shift for shake frames. No Pillow on the device |
| `package.py` | Import (only the contract's paths are unpacked; no `..`, absolute paths, links or encrypted entries; sizes checked on the bytes read; the theme is checked in a temporary folder and only then moved into place), export (adds `GUIDE.md`), duplicate, list, delete |
| `customize.py` | The Duplicate screen's choices (accent / background presets, icon set, pointer, text size; re-deriving from the palette), live preview data, theme ids from names, where theme files are looked for |
| `preview.py`, `app.py` | The preview picture (cairo) and the Theme app's window (GTK); not used by tests without a display |
| `current.py` | For apps: the rendered `theme.env`, colours per part, the icon folder (no other imports) |
| `render.py` | Writes `theme.env`, Waybar / mako / labwc / wlogout / nwg-drawer / foot configs, the flat `icons/` folder and the `Handtop-Current` GTK icon theme into one folder, swapped in whole |
| `guide.py` | `GUIDE.md`, generated from the schema |
| `builtin.py` | Assembles the built-in `handtop-dark` / `handtop-light` themes from `src/theme/themes/<id>/theme.json` and the generated pixel art in `overlay/` |

Decisions (2026-11-10): rendered files go to `~/.local/state/rg35xxh/theme/` (a cache may be cleared), `theme.env` included (one generated set in one place); `~/.config/rg35xxh/theme` keeps only the choice (the theme id); part colours a theme leaves out are derived from its own palette, so a palette-only theme still looks consistent; input-mode shake frames may be drawn by the theme, otherwise the whole icon is shifted; Wi-Fi tray icons are optional in a theme, Bluetooth tray icons are a slot.

Tests: `python3 -m pytest -q src/theme/tests` (also in `tools/ci-checks.sh`). `test_builtin_look.py` checks that the built-in themes render to the same rules and colours as today's configs and palettes, with each intended difference listed.
